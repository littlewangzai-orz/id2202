 ## Front-end

 The code file related to the Front-end is as following:**src/ast.c**, **include/ast.h**, **parser.y**, **scanner.l**

**Parser.y** is a bison file and **scanner.l** is a flex file. They are used to build the front-end part.
### the use of flex and bison
 Bison and Flex, when used together, can transform user-provided grammar rules into a syntax parser.

 In simple terms, starting from the four grammar productions in the previous chapter, we went through a series of complex construction processes and ultimately obtained an action table. 
 
 This action table was then utilized to parse sentences. Bison is precisely responsible for this task; it reads the grammar productions provided by the user, generates a LALR(1) action table in C language format, and incorporates it into a C function named yyparse. 
 
 The role of this function is to parse the token stream using the action table, while this token stream is obtained by scanning the source program with a lexical analyzer generated by Flex.

 That's the basic structure of my project, and i will analze them by the order of front-end and back-end.

 ### the use of ast.h and ast.c

These two files provide a basic structure of Abstract syntax tree, so that i can use it in parser.y to build a parser.

It also provides some simple function like ``Create_Node``, using for creating a node, ``print_ast``,using for print the whole ast recurisvely and it is very useful for debugging, ``free_ast`` used for free the ast tree. The ``traverse_ast`` and ``is_only_eint_binop`` is used for simplifying the back-end part. For example, if there is a statement like:
``` int x = 1 + 1 + 1 + 1 + 1 + 1; ``` and it will be simplified to ```int x = 6;```
It will use a lot of temp regs so that the mem might be drained, like there is an example in git's test.So the solution i take is to get the result in advance instead of just using a lot of regs.

## Back-end 
Speaking of the back-end part, it is much more difficult than the front-end part, since i use C as my coding language, so there will be much much more additional part for me to write.The code related to this part is as following ``acc.h/c``, ``env.h/c``, ``ASM_IR.h/c``,``hybrid_IR.h/c``, ``reg2stack.c/h``.As there is no possibilty for me to write down all the function and uses of the whole file.I will just explain the purpose of them.

Firstly, i will talk about the ``env`` and ``acc``, they are used for simulating the env and acc part in the Ocaml.

The ``acc`` provide some functions as ``init_accumulator, 
add_print_accumulator, free_accumulator,replace_virtual_registerregister_spilling``.And it also provides a strcuture called Accumulator.


The ``env`` is doing the same thing, it add some variables to the environment structure for the next step.


The ``hybrid_IR`` is used to make the ast produced by the front-end to the hybrid_IR, the core function is the ``convertASTToIR``.The basic idea of this is to traverse the whole AST and add corresponding statements to the Hybrid_part, the logic is generated from the Lecture 8.

The ``ASM_IR`` is kind of the same, but convert Hybrid_IR to ASM_IR, the logic is also generated from the Lecture 8

The ``reg2stack`` is used for the register spilling.
